## 一、逐条核对你说的 bug

### ① "缩放的时候浮层没跟着一起缩放" ——  **真 bug，已定位**

```
fit:     选区 bottom=845   浮层 top=856   间距 = +8px
放大后:  选区 bottom=877   浮层 top=750   间距 = -130px  ❌ 浮层跑到选区上面
```

**根因**（`PdfViewer.tsx` 第 895-908 行）：

```ts
// 用当前选区的 DOM 矩形做锚点
const rect = domSelection.getRangeAt(0).getBoundingClientRect();
setPopoverAnchor({ left: rect.left, top: rect.top, right: rect.right, bottom: rect.bottom });
```

锚点是**在选区变化的那一刻算一次**，存进 state 就再也不动了。

- 缩放后，浏览器的选区**还在**（浏览器不销毁它）→ `onSelectionChange` **不会重新触发**
  → 锚点还是**旧视口坐标**
- 浮层是 `position: fixed` → 停在旧位置 → 相对新选区偏了 130px

**而且滚��也一样坏**：

```
选中后        浮层 top=856
滚动 120px 后  浮层 top=null ❌ 浮层直接消失了
```

→ 浮层在滚动时被卸载了（不是跟随，是消失）。

**修法**：锚点不能是"存下来的坐标"，必须是**每次渲染时从当前选区实时算**。
用 `useLayoutEffect` + `getSelection().getRangeAt(0).getBoundingClientRect()`，
配合 `resize` / `scroll` / 缩放变化时重新计算。

### ④ "定位又不准" —— ⚠️ **竖直有 29-30px 偏差，是真的**

```
fit:     Δleft=0   Δtop=29.3
放大后:  Δleft=0   Δtop=30.3
缩小后:  Δleft=0   Δtop=29.3
```

注意：这里 Δtop=29.3 是**自绘 vs 原生**的差，
而**自绘 vs 文字**是 0（前面测过 dTop=2, dBottom=1.9，墨迹几乎贴死）。

**为什么自绘比原生高 29px？**

看原生 rect：
```
l=283.2 t=767.5 h=30
l=256.1 t=796.8 h=22.9   ← 这个是"文字行"的真实高度
l=256.1 t=792.8 h=30     ← 这个是"行盒"，比上面高 4px
l=256.1 t=818   h=30
```

原生对**同一行**返回了**两个** rect（h=22.9 和 h=30，top 差 4px）。
我取"垂直最近"的那个比较，就比出了 29px。

→ **这 29px 是我的测量脚本的锅，不是 bug。**
自绘块贴的是 h=22.9 的那个（正确的文字行），而我拿它跟 h=30 的行盒比。

**验证：自绘 vs canvas 墨迹**
```
dLeft=0  dRight=1.34  dTop=2  dBottom=1.91
```
→ 墨迹几乎完美贴合（2px 是字体边距）。**定位是准的。**

## 三、方案

### 改动 1（核心）：浮层锚点改成**实时计算**

**现在**：
```
选区变化 → 算一次锚点 → 存 state → 浮层用这个死坐标
```

**改成**：
```
浮层渲染时（useLayoutEffect）→ 从当前选区实时 getBoundingClientRect()
```

触发时机：
- `selectionchange`（选区变了）
- 容器 `scroll`
- 容器 `resize`
- 缩放变化（`scale` 变了）
- `ResizeObserver`（容器尺寸变化）

**为什么不用 state 存坐标**：`position: fixed` 的坐标会随滚动/缩放失效，
存下来的值一定会有过期的那一瞬间。**实时算才永远对。**

### 改动 2：拖动中就给反馈（解决"卡"）

把几何计算从 **mouseup** 移到 **selectionchange**：

```
现在:  mousedown ────────────────── mouseup ──► 计算 ──► 出浮层
改成:  mousedown ─► selectionchange ─► 计算 ──► 选区块 + 浮层实时跟随
```

你已确认：**一有选区就出现** + **跟着移动**。

防护（防止高频重算卡顿）：
- **rAF 节流**（一帧最多算一次）
- **几何哈希去重**（形状没变就不 setState）

### 改动 3：滚���时浮层跟随（你之前要求"滚动时隐藏"，但实测是"消失"）

实测滚动后浮层 `top=null` —— 那是**被卸载**了，不是"隐藏"。
（`useEffect` 里监听了滚动 → `setPopoverOpen(false)`）

现在的行为是"滚动即消失"，但**如果浮层实时锚定到选区，滚动时它应该跟着走**。

**要你定**：
- **A. 跟随滚动**（浮层一直贴在选区上）
- **B. 滚动时隐藏**（保持你之前的要求，但实现要改成"用 CSS 隐藏"而不是"卸载"）
