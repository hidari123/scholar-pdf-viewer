chore(dev): 固定 demo 端口为 5180 + 统一 E2E 基址

用户反馈："你启动一下这个项目 启动在哪里 为什么你每次起的端口都不一样 固定一个端口"

## 端口为什么每次都不一样

**两个原因叠加**：

1. **`demo/vite.config.ts` 没配 `server.port`** → Vite 默认用 **5173**，被占用就往后找
2. **Vite 默认会"偷偷换端口"** —— 5173 → 5180 → 5200 → 5201 …

而我自己为了避开占用，**每次手动换一个端口**（5180 / 5181 / 5200 / 5201），
再手动设 `E2E_BASE_URL` → 地址完全不可预测。

## 改动

### ① `demo/vite.config.ts`：固定端口 + `strictPort`

```ts
server: {
  port: 5180,
  strictPort: true,   // ← 关键：端口被占用时**直接报错**，不偷偷换
  host: '127.0.0.1',
  open: false,
},
```

`strictPort` 是重点：没有它，Vite 会在端口被占用时**自动往后找一个**
→ 地址再次变得不可预测。现在是**响亮地失败**。

### ② 新增 `scripts/demo.mjs`（`pnpm demo` 的入口）

- 打印固定地址（`http://127.0.0.1:5180`）
- 端口被占用时给出**明确提示**（而不是让人猜）
- 统一用 `127.0.0.1`（不用 `localhost` → 避免 IPv6 `::1` 和 IPv4 `127.0.0.1` 的歧义，
  之前 `localhost` 在 Windows 上会解析到 `::1`，而 Vite 监听的是 `127.0.0.1`）

### ③ 新增 `scripts/e2e-base.mjs`：所有 E2E 脚本的**唯一**基址来源

之前 **17 个脚本各自写了一个默认端口**：

```
5180 / 5181 / 5187 / 5190 / 5194 / 5196 / 5198 / 5200 …
```

→ 跑一次 E2E 有一半脚本连不上，除非手动设 `E2E_BASE_URL`。

现在全部统一：

```js
// scripts/e2e-base.mjs
export const DEMO_PORT = 5180;
export const E2E_BASE_URL = process.env.E2E_BASE_URL ?? `http://127.0.0.1:${DEMO_PORT}`;
```

**跑 E2E 不需要再手动设环境变量**。

### ④ README + DEVLOG 记录

- README 加了「启动（固定端口 5180）」章节（含端口占用的处理命令）
- E2E 脚本表从 11 套 96 项更新为 **16 套 181 项**
