fix(selection): 选区/高亮与文字精确对齐 + 浮层单帧渲染

## 查了 pdf.js v6 源码, 对比出 3 个关键差异

### 1. 选区/高亮比文字高 11px、偏上 6px（核心 bug）

**实测**（真实 PDF, 230%）:
  浏览器选区矩形: y=231.92, h=44
  文字本身 (span): y=237.92, h=33
  -> 偏上 6px, 框高多 11px

**根因**: 浏览器的选区矩形 = **字体的自然行盒**(ascent+descent+lineGap)
而 span 的 box = fontSize x line-height
**CSS 改不动它**（实测 7 种全无效）:
  line-height 1/0.9/0.62 -> 44/44/30px
  height 1em + overflow hidden -> 44px
  display inline/inline-block -> 44px
  transform scaleY(0.65) -> 20px 但**字被压扁**

**pdf.js v6 也用 getClientRects()**（pdf.mjs:4228）,
关键在 CSS: `.textLayer { line-height: 1 }` -> span 的行盒 = fontSize
本包也设了 line-height:1 但没用:
span 的 top = 基线-ascent, 浏览器行盒从 top 往下 fontSize 高
-> 其基线位置 = top + **浏览器字体的 ascent'**（≠ 我们实测的 ascent）-> 差 6px

**修法: 用文本项的基线裁剪**
  水平: 保留 getClientRects() 的 left/width（浏览器知道字距/kerning/连字）
  垂直: 用文本项的基线 + 字形 ascent/descent 自己算

**实测效果**:
  选区 rect      y=231.92 h=44  ->  y=237.92 h=32.996
  与文字 Δtop    6px           ->  0.002px
  与墨迹 Δtop    10px          ->  4px
  与墨迹 Δbottom 12px          ->  7px
  高亮 vs 文字   10px          ->  0.0px

新增 src/core/selection/item-geometry.ts + clipToBaseline()

### 2. transform 顺序反了
pdf.js: `rotate(var(--rotate)) scaleX(var(--scale-x)) scale(var(--min-font-size-inv))`
本包旧: `scaleX(...) rotate(...)`
-> 先横向拉伸再旋转, 对旋转文字结果完全不同
-> 已改成 `rotate() scaleX()`

### 3. 浮层两帧渲染 -> 单帧
浮层要先渲染出来量尺寸, 再算位置 -> 两帧
尺寸只跟动作数量有关（按钮固定 28px）-> 可预估:
  width  = 4*2 + 1*2 + 按钮数*28 + 分裂按钮*16 + 2*(按钮数-1)
  height = 4*2 + 1*2 + 28
-> `measured ?? estimatedSize` -> 只渲染一帧
**实测**: 27-33ms -> 21-25ms

## 测量教训（又一次）
一开始用 waitForFunction 测延迟得到 130-150ms
-> 那是 **waitForFunction 的轮询量化**（rAF/100ms 间隔）, 不是真实延迟
改用 MutationObserver 打时间戳 -> 真实值 **27ms**
**教训**: 测延迟要用 MutationObserver/PerformanceObserver 打点
