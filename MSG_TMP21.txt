fix(selection): 修复多行选择漏选（"中间有的没有底色"）

用户反馈："现在选择文字的时候如果选择了多行 中间有的会没有出现底色，
就是看起来漏选了一些地方 之前这个bug是没有的"

## 实测（修复前）

```
nativeCount: 14   （浏览器选了 14 个矩形）
drawnCount:  6    （只画出来 6 个）
uncovered:   7    （7 个矩形没有底色！）← 用户看到的"漏选"
```

## 根因：拖动范围过滤太严格

浏览器会把选区**扩展到行首 / 词边界**：

```
拖动:  x=487 → 607
选区:  x=108 → ...      ← 左边整行都被包进来了（差 380px！）
```

→ 之前按"**和拖动范围有重叠**才保留"过滤
→ **行首那部分全被丢掉** → 中间的行就没底色了。

## 修法：改成"离群才丢"

```ts
// ❌ 之前：和拖动范围有重叠才保留
return rect.left < rangeTo && rectRight > rangeFrom;

// ✅ 现在：离得太远才丢（> 450px）
const gap = rect.left > to ? rect.left - to : rectRight < from ? from - rectRight : 0;
return gap <= OUTLIER_DISTANCE;
```

阈值 **450px** 的由来（两个矛盾要同时满足）：

| 场景 | 距离 | 结果 |
|---|---|---|
| 浏览器扩展到行首 | ~380px | **保留**（是用户选的那一行） |
| 页边戳（另一个"离群"） | ~780px | **丢掉**（根本不是那一行的内容） |

## 实测（修复后）

```
nativeCount: 14   drawnCount: 6    uncovered: 0   ← ✅
```

## 顺带澄清一个我自己的误判

我一度以为"基线表是视口坐标，矩形是页内坐标"→ 在 `buildSelectionShapes` 里加了一次换算
→ **Δtop 从 0.01px 变成 4px**（候选挑错）。

实测证明：**`item.top` / `item.left` 本来就是"页内坐标"**
（`tx = viewport ∘ item` 把 PDF 单位映射到页像素，而页元素本身就是页像素宽）
→ **不需要换算** → 已还原，并把这个结论写进注释（避免以后再踩）。
