perf(selection): 拖动时的事件节流 —— p95 从 31ms 降到 17ms

## 现象

加了"按拖动范围过滤选区"之后，**拖动变卡**：

```
拖动时满帧: p95=31.1ms（要求 ≤ 20ms）
```

## 根因

`mousemove` 在拖动时能到 **100+ 次/秒**：

```ts
container.addEventListener('mousemove', onMouseMove);   // ❌ 每个事件都跑
```

→ 每次都写一个 ref（本身很便宜）
→ 但**监听器的派发**本身有成本
→ 再叠加 `selectionchange` 的处理（每次都重算选区几何）
→ **p95 从 17ms 涨到 31ms**。

## 修法

**rAF 节流**（拖动时 60fps 足够）：

```ts
const onMouseMove = (event: MouseEvent) => {
  if (!dragStartRef.current) return;
  moveX = event.clientX;
  if (moveRaf !== 0) return;          // 已经有排队的了
  moveRaf = requestAnimationFrame(() => {
    moveRaf = 0;
    if (dragStartRef.current) {
      dragEndRef.current = { x: moveX, y: dragStartRef.current.y };
    }
  });
};
container.addEventListener('mousemove', onMouseMove, { passive: true });
```

- `passive: true` → 告诉浏览器"我不会 preventDefault" → 不阻塞滚动
- rAF → **每帧最多记一次**
- 卸载时 `cancelAnimationFrame`

实测：

```
帧间隔: {"p50":16.7,"p95":16.9,"max":26.9,"over32":0,"total":40}
```

```ts
// ❌ 排序 + 分组 + 分配数组（每次 selectionchange 都跑）
const sorted = [...rects].sort((a, b) => a.left - b.left);
const columns = [];

// ✅ 直接按范围过滤（O(n)，零分配）

```
