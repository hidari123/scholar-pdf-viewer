test(e2e): 加浮层锚定回归断言（复现缩放/滚动/拖动中浮层的问题）

用户实测反馈（2026-11-17）:
- "缩放的时候浮层没跟着一起缩放"
- "缩小之后选择跑偏很厉害"
- "很卡"（拖动中完全没有反馈）

## 新增 scripts/e2e-popover-anchor.mjs（8 项断言）

断言的是**浮层与选区的间距**，而不是坐标:
间距在缩放/滚动前后应该**保持一致**（基准 8px）。

## 当前结果: 4/8（**故意是红的**，复现 bug）

```
PASS 选中后浮层出现
PASS 浮层锚定在选区下方 - 间距 8px
FAIL **缩放后浮层仍锚定在选区上** - 间距 nullpx（基准 8px）
FAIL **缩小后浮层仍锚定在选区上** - 间距 nullpx（基准 8px）
FAIL **滚动时浮层跟随**（不消失、不跑偏） - 间距 nullpx → nullpx，浮层消失
FAIL **拖动中浮层已出现**（不用等松手） - 已选 4 字符
PASS **拖动中选区块已出现** - 3 个
PASS 全程无 JS 错误
```

## 复现的根因

1. **缩放/滚动后浮层消失**:
   `PdfViewer.tsx` 里滚动时直接 `setPopoverOpen(false)`（"隐藏"）
   + 缩放时锚点是**选区变化那一刻算一次**的坐标（存 state）
   -> `position: fixed` 的坐标过期 -> 浮层跑到别处或消失

2. **拖动中浮层不出现**:
   所有几何计算都挂在 **mouseup** 上（`useTextSelection` 的 `onMouseUp`）
   -> 拖动过程中完全没有反馈 -> 手感"巨卡"
   （自绘选区块反而是有的 -> 说明 `onClientRects` 在 selectionchange 里被调了，
     但浮层的开关只在 mouseup）

## 之前几轮"全绿"为什么没发现

之前的 E2E 全部只断言**几何**（选区块的位置对不对），
**从没有断言过"浮层在不在、跟不跟得上"** —— 而用户抱怨的正是后者。
