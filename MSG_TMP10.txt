feat(highlight): 高亮后彻底清选区 + 点高亮弹出操作条（复用选区浮层样式）

用户反馈：
1. "点击高亮之后 发现无法取消选中状态 一直都有外边框"
2. "点击高亮之后 应该也会出现那个选择的弹框的 可以选择颜色等"

## 实测（复现）

```
选中后:      nativeSelLen=11  selectionLayer=1  popover=true
点高亮后:    nativeSelLen=11  selectionLayer=1  popover=true   ← ❌ 全都没清
点高亮块后:  activeAnnotations=1                                ← ❌ 只有个蓝框
```

## 根因（挖了 5 层才找到真正的原因）

### ❌ 表层原因 1：`clearState()` 没清浏览器原生选区

`useTextSelection.clearState()` 只清包内引用 → 浏览器原生选区还在
→ `selectionchange` 还会触发 → 浮层又被打开。

→ 修：新增 `clearNativeSelection()`。

### ❌ 表层原因 2：高亮块挡住了文字选择（**真正的元凶**）

`.scpdf-annotation { pointer-events: auto }` → 高亮块是 `<button>`，
**正好盖在文字上** → 用户在那一块**框选不了字**。

实测（拖动起点）：
```
拖动起点元素: BUTTON.scpdf-annotation scpdf-annotation--mine
```

→ 修：改成 `pointer-events: none` + **容器级事件委托**（和链接层一个套路）。

### ❌ 表层原因 3：`removeAllRanges()` 破坏后续选择

```
点高亮后重选: 0 字符
selectionchange 事件: []   ← 浏览器一个事件都没发
```

`removeAllRanges()` 把浏览器推进"选区被程序改过"的状态
→ 后续拖动被浏览器吞掉。

→ 修：改用 `collapseToStart()`（视觉上"没选中"，但不改浏览器的选区控制器）。

### ❌ 表层原因 4：Esc 只关浮层、不清选区 → 之后收不到 mouseup

```
首次 mouseup: ["SPAN.scpdf-text-layer__item"]
Esc 后 mouseup: []          ← ❌ 浏览器一个 mouseup 都不发
```

→ 浏览器仍认为"用户在操作选区" → 之后的拖动收不到 mouseup
→ 选区不再更新 → **浮层再也不出现**。

→ 修：Esc = 彻底取消选择（新增 `onDismiss` 回调）。

### ❌ 表层原因 5：点工具栏时浮层不关

点 `<button>` 时浏览器**不会清掉**旧选区 → "还有选区" → 不关 → 浮层赖着不走。

→ 修：区分"点在文本层里"（等选区变化）和"点在文本层外"（立刻关）。

## 本次改动

### ① 清选区（三管齐下，顺序有讲究）

```ts
const clearSelectionAfterHighlight = useCallback(() => {
  // 1) 先清浏览器原生选区（会触发 selectionchange）
  textSelection.clearNativeSelection();
  // 2) 再清包内部状态（不通知宿主）
  textSelection.clearState();
  setSelectionShapes(new Map());
  setPopoverOpen(false);
  setPopoverAnchor(null);
  setCurrentSelection(null);
  // 3) 去掉高亮的"激活"蓝框
  setActiveHighlightId(null);
}, [textSelection]);
```

`clearNativeSelection` 的实现要点：
- **下一帧**再清（rAF）→ 浏览器的事件循环回到"空闲"
- **用 `collapseToStart()`** 而不是 `removeAllRanges()`
- **把焦点还给容器**（点在按钮上时焦点在 `<button>` → 没法开始新的文本选择）
- rAF 的取消**只在卸载时**做（不能放在主 effect 的 cleanup 里 ——
  那个 effect 依赖 `pageFrames` 等，会随重渲染重跑 → 把还没执行的清除操作取消掉）

### ② 高亮块操作条（复用选区浮层样式，只换锚点）

- `SelectionPopover` 新增 `anchorRect` → 给了就用它，不再读浏览器选区
- 新增 `src/core/selection/highlight-actions.ts` → `buildHighlightActions()`
- 动作：🖍换色 / 📋复制 / 🗑删除 / 更多
  - **宿主没传回调 ⇒ 对应按钮不渲染**（和选区浮层一致）
- 高亮块加 `data-highlight-id` → 事件委托按 id 定位
- 蓝框改成 **1.5s 自动消失** + hover 显示（不再永久挂着）

### ③ 宿主的统一入口

- 新增 `onHighlightCreate`（包→宿主）：宿主创建高亮后通知包 → **包负责清选区**
  （"清选区"是 UI 行为属于包；"存高亮"是业务属于宿主）
- 新增 `onHighlightColorChange` / `onHighlightCopy` / `onHighlightMore`
- 新增 `PdfViewerHandle`（React 19 的 `ref` prop）：
  ```tsx
  const ref = useRef<PdfViewerHandle>(null);
  ref.current?.clearSelection();   // 宿主自己实现了高亮按钮 → 手动清
  ```

## 顺带修的 bug

### 缩放后选区位置跑偏（Δtop = 16.48px）

缩放后文本层是**异步**重建的 → 基线表在选区形状算完之后才更新
→ 形状是用**旧缩放**的基线裁出来的。

→ 修：基线表变化时**重新采集** client rects + 用新基线重算形状。

### 坐标系不一致（`scrollLeft`）

`buildSelectionShapes` 的 `toContentX` **没有** `scrollLeft`，
但 `useTextSelection` 里的 rect.left **有** → 两个空间混用 → 缩放后整体偏移。

→ 统一成**视口相对**（水平）和**内容相对**（垂直）。

## 顺带修的构建问题

`demo/vite.config.ts` 的 alias：
- `import.meta.url` → Vite 打包后指向临时文件 → 路径错
- `node:path` + `process` → demo 没装 `@types/node` → typecheck 失败
- 相对路径 → Vite 的 alias 必须绝对路径

→ 改用 `import.meta.dirname`（Node 20.11+）→ 绝对路径 + 不受打包影响
→ demo 加 `@types/node` devDependency
