fix(selection): 缩放后按**文字**恢复选区 + 重新框选浮层能重开

上一轮（浮层实时锚定）的实现有**两个真 bug**，这轮修掉。

---

## Bug A：缩放后恢复出"整页"选区（88 字符 → 2938 字符）

### 实测

```
snapshot {startOffset: 72, endOffset: 3010, pageNumber: 1, len: 88}
→ 恢复后 selLen = 2938
```

`endOffset=3010` 而选区只有 88 字符 → **偏移算错了**。

### 根因（三个坑叠加）

**① 坐标系不一致**
`offsetOf` 累加的是**所有页**的 span（跨页偏移），
而 `restoreSelection` 只在**一页内**找 → 位置错乱。

**② 累加方式不一致**
`offsetOf` 按 `span.textContent` 累加，
`restoreSelection` 按**文本节点**累加
→ span 里有元素子节点时两者漂移。

**③ 结束节点是元素，不是文本节点**
选区结束在 span 边界上时，`range.endContainer` 就是那个**元素**
→ 文本节点循环找不到 → 退回"span 末尾" → 偏移跳到很远。

### 修法：**不按偏移，按文字找**

缩放前记住"选中了什么**文字**" + "在哪一页"，
缩放后在这一页里**找到这段文字** → 重新选中。

```ts
// 拼出该页全文 → indexOf(目标文字) → 映射回 (文本节点, 节点内偏移)
```

→ 稳定、无坐标系问题，也符合用户直觉（选的还是那段字）。

## Bug B：缩放后**重新框选**，浮层再也不出现

### 实测

```
选中后         {len: 88, pop: true}
缩放后         {len: 88, pop: true}
缩放后重新选   {len: 88, pop: false}    ← 选区有了，浮层没了
```

### 根因

浮层的 `mousedown` 处理器：点在浮层**外面** → `onClose()` → 浮层关闭。

**重新框选的 mousedown 也落在浮层外面** → 浮层被关
→ 之后新的选区建立 → `handleSelectionChange` 想开浮层
→ 但 `popoverOpen` 已经是 `false` → **需要一次状态变化才能重开**
→ 时机上没接上 → 浮层再也不出现。

### 修法

按下时**不立即关闭**，而是 `setTimeout(0)` 推迟到 mousedown 之后：

```ts
setTimeout(() => {
  const selection = window.getSelection();
  const hasSelection = /* 有选区 */;
  if (hasSelection) return;      // 产生了新选区 → 不关（由选区变化决定开/关）
  onClose?.();                    // 点空白 → 关
}, 0);
```

## 另外修的：恢复循环被重复触发

上一轮用 `lastScaleRef` 当"要不要保存"的判据，
**连续缩放两次**（放大→缩小）时守卫会跳过保存 → 快照是旧的 → 恢复失败。

→ 改成宿主**显式调用** `save()`（在改缩放之前）+ `pendingSaveRef` 只做标记。

⚠️ 并且发现：**恢复循环里绝不能再调 `save()`** ——
它发生在重渲染之后（选区已被销毁）→ 会把好快照**覆盖成 null**。

实测日志：
```
[PRES] save() called, pending= true      ← 宿主显式调（好快照）
[PRES] save() called, pending= true      ← 循环里又调（覆盖成 null）❌
```
