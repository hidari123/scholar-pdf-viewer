test(panel-offset): 修正垂直基准 —— 面板开合时的选区定位断言全绿

之前 E2E 一直有 **1 项失败**（"有面板：选区块位置正确" Δ上=5），
而且**基线也同样失败** → 一直当成"既有问题"放着。

这次逐行审计后**定位到是测试的基准错了**，不是代码错了。

## 根因：垂直基准用了"行盒"，而自绘块贴的是"字形"

浏览器的 `client rect` = **字体的自然行盒**（比文字高、偏上），
而自绘的选区块是**刻意贴着字形**的（这样高亮块和文字才对齐）。

实测（真实 PDF，开面板时）：

```
clientTop = 321.19   ← 行盒（浏览器给的）
spanTop   = 326.00   ← 字形（文字实际的位置）
drawnTop  = 326.20   ← 自绘块 ✅ 贴着字形（差 0.2px）
```

→ 和行盒比 → **天然差 2~5px** → 那是**正常的**，不是定位错了。

而且这个差值**和面板开不开无关**（是字体的固有行高）
→ 用行盒当基准 → **字号大的行差得多** → **误报**。

## 修法

基准改成**被选中的文字 span 的 top**（= 字形盒的 top）：

```ts
const inkSpans = [...document.querySelectorAll('.scpdf-text-layer__item')]
  .filter((x) => range.intersectsNode(x));
const inkTop = inkSpans.length
  ? Math.min(...inkSpans.map((x) => x.getBoundingClientRect().top))
  : Math.min(...selectedSpans.map((r) => r.top));   // 兜底
```

## 结果

```
PASS 无面板：选区块位置正确（Δ ≤ 3px） - Δ左=0 Δ上=0
PASS 有面板：选区块位置正确（Δ ≤ 3px） - Δ左=0 Δ上=0
PASS 面板关闭后：选区块位置恢复正确（Δ ≤ 3px） - Δ左=0 Δ上=0
```

**Δ上 从 2 / 5 / 2 → 0 / 0 / 0**（说明自绘块本来就精确对齐字形）
