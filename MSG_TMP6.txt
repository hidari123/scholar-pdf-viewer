## 🔴 真 bug：页居中时选区被**整段丢弃**

### 实测

100% 缩放（容器 1384px 宽，页 612px 宽）：

```
浏览器选区: { len: 26, clientRects: 1 }      ← 浏览器选区正常
自绘选区层: { layers: 0, rects: 0 }           ← ❌ 什么都没有！
```

用户看到的现象：**低缩放下选中没反应**。

### 根因

`.scpdf-page` 用 `margin-inline: auto` **居中**：

```css
.scpdf-page { position: absolute; left: 0; right: 0; margin-inline: auto; }
```

→ 当页宽 < 容器宽时（低缩放 / 适合页面），页会**居中偏移**。

而页框的 `left` 被**写死成 0**（两处）：

```ts
// PdfViewer.tsx
pageFrames: pageSizes.map((size, index) => ({
  pageNumber: index + 1,
  top: pageTops[index] ?? 0,
  left: 0,        // ← ❌
  ...
}));

// handleSelectionClientRects 里还有第二处
buildSelectionShapes(rects, pageSizes.map((size, index) => ({
  pageNumber: index + 1,
  top: pageTops[index] ?? 0,
  left: 0,        // ← ❌
  ...
})), ...);
```

→ 归页判定（`pageOfRect`，按**中心点**落在页框内）：

```
页实际 left = 386
选区矩形 centerX = 681.5
按 left=0 判定：  681.5 > 0 + 612  → **不属于任何页** ❌
                → 矩形被 `continue` 掉 → byPage 为空 → 返回 null
                → 自绘选区层为空
```

### 修法

**量出页的真实 left**（不靠算，靠量 —— 能自动处理 padding / 滚动条 / 居中规则变化）：

```ts
const [pageLeft, setPageLeft] = useState(0);

// ResizeObserver 观察容器和页 → 页宽变化（缩放）也会改 left
const measurePageLeft = () => {
  const pageEl = container.querySelector<HTMLElement>('.scpdf-page');
  if (!pageEl) return;
  // ⚠️ 用 offsetLeft，不要用 getBoundingClientRect() 相减
  //    （布局未稳时会算出错值：实测先算出 395，后面变成 8、0……）
  const left = Math.round(pageEl.offsetLeft - container.offsetLeft);
  setPageLeft((prev) => (Math.abs(prev - left) >= 1 ? left : prev));
};
```

两处 `left: 0` 都改成 `left: pageLeft`。

### 回归测试

`src/core/selection/extract.test.ts` 加了 2 个用例：
- 页居中（left=386）时，选区仍能归页、且页内坐标正确
- 页居中时，页外的矩形仍返回 null

## 验证工具：画布墨迹探针

新增 `scripts/e2e-canvas-ink-probe.mjs`。

### 为什么必须跟"画布墨迹"比

浏览器自己的选区 rect 高度 = 字体的**自然行盒**（比文字本身高 ~30%）
→ 拿它当基准会得出"偏了 7px"的假结论（之前踩过）。

pdf.js 把文字画在 canvas 上 → **canvas 的像素位置就是文字的真实位置**。

### 探针的两个关键设计

**① 逐行扫描**（不能把整个包围盒的墨迹合起来）
选区矩形是**逐行**的 → 合并后上下相邻行的字也会被算进来 → Δ上/Δ下 假得离谱。

**② 只扫"中间带"**（rect 垂直方向的 25%~75%）
选区矩形是 **em 盒**（= fontSize），比实际字形高
→ 上下的空白里可能有**相邻行**的字（行距小时）→ 同样会污染。

### 垂直方向不能直接比墨迹

选区高度 = **em 盒高度**（= fontSize），和 pdf.js 的 `--font-height` 一致。
墨迹高度 = **实际字形高度**（cap-height / x-height）。
→ 大字号（标题）时两者差很多（实测 28.69px 字号 → 墨迹只有 20px）。
→ 那是**字体本身**的性质，不是选区不准。

→ 垂直改成：**选区必须完全包含墨迹**（不切字形）+ 留白 ≤ em 盒的 60%。

## 测试脚本本身踩的坑（记录，避免以后重犯）

1. **不能直接删 React 渲染的 DOM**
   `document.querySelectorAll('.scpdf-annotation').forEach(el => el.remove())`
   → React 的 DOM 状态和实际 DOM 对不上 → **下一次渲染时 React 清掉整个文本层**
   → 下一档位 `spans: 0` → "找不到正文"（假失败）。

2. **候选 span 要逐个试**
   真实 PDF 左侧的**旋转戳**（`transform: matrix(0.85,0,0,1,0,0)`）
   → mousedown 落在它上面 → 浏览器**不创建选区**（旋转文字不参与选区）
   → 但它的 `getBoundingClientRect()` 看起来完全正常 → 静态检查发现不了。
   → 而且旋转戳的 `getBoundingClientRect()` **高度远大于行高** → 按它算 y 会落到别的行。

3. **选区"太长"说明拖过了整页** → 要拒绝并重试（否则量的是整页）。

4. **性能测试之后坐标会过期** → 要**重新找候选**（合成事件会改选区和滚动位置）。

5. **合成事件（fire('mousedown')）会让浏览器处于"正在拖选"状态**
   → 下一档位的真实拖动被并入 → 选区为 0
   → 要先 `mouse.move` 移开 + `Escape` + `removeAllRanges` 清场。

6. **缩放后要等文本层重建完**（`waitForFunction(spans > 20)`）→ 否则查到 0 个。
